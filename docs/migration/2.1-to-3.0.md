# Migrating from schema 2.1 to schema 3.0

Status: draft on branch `v3-design`. Announced: ANNOUNCED_ON. Earliest release tag: EARLIEST_TAG.

## Summary

Schema 3.0.0 is a MAJOR release under [VERSIONING.md](../VERSIONING.md): documents that validate against 2.1.0 can fail against 3.0.0. It carries four breaking changes.

| Change | Area | Breaks |
|---|---|---|
| A | `evidence_basis` values renamed | Every tactic carrying `operational_primary`, `hybrid`, or `literature_primary` |
| B | Lifecycle contract added | Nothing in current data; new conditional rules apply when the fields are used |
| C | Tightening | Documents with malformed IDs, keys, versions, actor-profile values, or contradictory severity and modality fields |
| D | Unused stubs removed or relaxed | Documents carrying a root `operations` key |

Also changed: the schema `$id` is now `https://jgulyash.github.io/THREAT-Matrix/data/3.0.0/framework.schema.json`, the schema root carries `"x-schema-version": "3.0.0"`, `schema_version` must match MAJOR 3, and `scripts/lint/validate.py` requires `schema_version` to equal `3.0.0` (check V24).

For the canonical document the required data changes are mechanical: rename 122 `evidence_basis` values, set `schema_version` to `3.0.0`, and drop the empty root `operations` array. No identifier changes. No tactic, indicator, countermeasure, response protocol, or actor profile is added, removed, or renumbered.

## Change A: evidence_basis value rename

### What changed

The tactic field `evidence_basis` keeps its name and stays required. Its enum values change.

| 2.1 value | 3.0 value |
|---|---|
| `operational_primary` | `practice_led` |
| `hybrid` | `practice_and_literature` |
| `literature_primary` | `literature_led` |
| `literature_only` | `literature_only` (unchanged) |

New field description: "Declares how the tactic was authored. practice_led: tactic structure and indicators were authored from practitioner experience, with public sources cited that corroborate the pattern. practice_and_literature: authored from practice and published literature together. literature_led: derived mainly from published literature with practitioner review. literature_only: derived from published literature with no practitioner origin claimed. Whatever the value, every tactic, indicator, countermeasure, and response protocol cites public sources only."

The TypeScript union `EvidenceBasis` in `src/types/framework.ts` carries the new values. `validate.py` check V25 rejects any other value and names the replacement when it sees a retired 2.x value.

### Why

The 2.1 names described the field as a grounding or provenance claim, and "operational" read as a claim about non-public operational data. The field describes how a tactic was authored. The new names say that directly, and the description states that every object cites public sources only, whatever the value. See METHODOLOGY.md for authoring method.

### Remediation

Apply the mapping above to every tactic. The mapping is one to one, so it is safe to automate. Consumers that switch on the value (filters, labels, register rules) must update their literals. A consumer that must read both 2.x and 3.x documents can normalize on read with the same mapping.

### Example

```jsonc
// 2.1                                   // 3.0
{                                        {
  "id": "TM0103",                          "id": "TM0103",
  "evidence_basis": "operational_primary"  "evidence_basis": "practice_led"
}                                        }
```

## Change B: lifecycle contract

### What changed

Five optional properties are added to `tactic`, `actor_profile`, `indicator`, `countermeasure`, and `response_protocol`:

| Property | Type | Rule |
|---|---|---|
| `lifecycle_state` | enum `active`, `deprecated`, `superseded`, `reserved` | Optional. Absent means `active` (schema `default: "active"`). |
| `deprecated_in` | SemVer string | Optional. The content version in which the item left `active`. |
| `superseded_by` | ID string, same namespace (pattern per namespace) | Required when `lifecycle_state` is `superseded`. |
| `deprecation_reason` | non-empty string | Optional. |
| `reserved_reason` | non-empty string | Required when `lifecycle_state` is `reserved`. |

The two requirements are schema `if`/`then` rules on each of the five definitions. `validate.py` check V26 adds what the schema cannot express: `superseded_by` must resolve to an existing ID in the same namespace, must not point at itself, and is illegal on any state other than `superseded`.

`deprecation_reason` is not one of the four fields first scoped for this change. It is included because [DEPRECATION.md](../DEPRECATION.md) uses it in its own required-field examples, and every object definition is closed (`additionalProperties: false`), so without it those documented examples would fail validation.

A per-release ID manifest format is added:

- `docs/data/id-manifest.schema.json` defines `{version, generated, ids: {tactics, actor_profiles, indicators, countermeasures, response_protocols, reserved}}`. Namespace lists hold active, deprecated, and superseded IDs; `reserved` holds reserved IDs from any namespace.
- `scripts/lint/id-manifest.py` reads `framework.json` and writes `docs/data/id-manifest-<version>.json`. With `--previous <manifest>` it exits 1 if any ID from the earlier release is missing, which turns the no-reuse guarantee in [IDENTIFIERS.md](../IDENTIFIERS.md) into a release check.

No manifest is committed on this branch yet; the first one ships with the 3.0.0 content release.

### Why

DEPRECATION.md has required a `lifecycle_state` field on every identified object since V1.1, but the schema never declared it, and every object definition is closed. A document that followed the deprecation policy was therefore invalid. 3.0.0 makes the documented policy expressible and enforceable.

### Remediation

Current data: AP022 and AP027 now ship as reserved actor profiles (id, lifecycle_state, reserved_reason only). Every other object omits lifecycle fields, and absence means `active`. Consumers should start filtering on `lifecycle_state` per DEPRECATION.md (show `active` by default, follow `superseded_by` for historical references). Treat a missing field as `active`.

Reserved shape: on all five lifecycle definitions, an object with `lifecycle_state: reserved` needs only `id`, `lifecycle_state`, and `reserved_reason`; the full required list applies to every other state. This models the relaxed shape DEPRECATION.md describes. Consumers that list actor profiles must skip reserved entries (the reference SPA, top-nav count, release audit, and Python consumer do).

### Example

```jsonc
// 2.1 (no way to express retirement)    // 3.0
{                                        {
  "id": "CM-0101-02",                      "id": "CM-0101-02",
  "measure": "...",                        "measure": "...",
  "source_refs": ["NTAC-MASS-2021"]        "source_refs": ["NTAC-MASS-2021"],
}                                          "lifecycle_state": "superseded",
                                           "deprecated_in": "3.1.0",
                                           "superseded_by": "CM-0101-05",
                                           "deprecation_reason": "Merged into CM-0101-05."
                                         }
```

## Change C: tightening

### What changed

| Rule | Where | Detail |
|---|---|---|
| Bibliography key pattern | `source_refs` items on tactic, indicator, countermeasure, response protocol | `^[A-Z][A-Z0-9]*(-[A-Z0-9]+)+$` |
| Bibliography key names | `bibliography` object | `propertyNames` with the same pattern |
| Tactic ID pattern | `related_tactics` items | `^T[MFOI][0-9]{4}$` |
| SemVer | `version` | SemVer 2.0.0 pattern |
| SemVer, MAJOR 3 | `schema_version` | `^3\.(0\|[1-9][0-9]*)\.(0\|[1-9][0-9]*)$`; any 3.x MINOR or PATCH validates, any other MAJOR fails |
| Floor not above band | indicator | `severity_floor: critical` requires `severity_band: critical` when both are present; `severity_floor: high` requires `high` or `critical` |
| Actor-profile enums | seven categorical fields | see the table below |
| Non-empty indicators | tactic `indicators` | `minItems: 1` |
| Crossing mechanism | indicator | `crossing_mechanism` is required when `modality` is `cyber_physical` and forbidden otherwise |

How the patterns were derived: the key pattern was read off all 52 live bibliography keys. Two keys do not end in a year (`LLNL-TR-858139`, `CISA-DISINFO-TACTICS`), so the pattern does not require the `-<YEAR>` suffix shown in IDENTIFIERS.md. The tactic ID pattern matches all 161 live tactic IDs and all 451 live `related_tactics` entries. Every live tactic has at least one indicator, so `minItems: 1` was safe to add. `severity_floor` is an enum of `high` and `critical`; the 43 live floored indicators are all `critical` with `severity_band: critical`.

The crossing-mechanism rule was not in the first change list. It is included because `validate.py` V21 already enforces it and its docstring states that the schema enforces the same rule, which was not true in 2.1. Live data already conforms (V21 is green), so it costs no data change.

Actor-profile enums. Values are every value present in the 32 live profiles, including odd ones.

| Field | Allowed values (3.0.0) |
|---|---|
| `category` | `lone_actor`, `insider`, `criminal`, `corporate_espionage`, `ideological`, `nation_state`, `customer_aggressor` |
| `category_label` | `Lone Actor`, `Insider`, `Criminal`, `Corporate Espionage`, `Ideological`, `Nation-State`, `Customer/Client Aggressor` |
| `awareness` | `witting`, `unwitting`, `negligent` |
| `direction` | `self_directed`, `criminal_directed`, `ideological_directed`, `state_directed` |
| `access_relationship` | `external`, `insider`, `authorized` |
| `phase_compression_risk` | `low`, `medium`, `high`, `very_high`, `n/a` |
| `actor_level` | `individual`, `group`, `organization` |

Values to clean in a later release (each is valid in 3.0.0 so that the cut needs no content decisions):

- `phase_compression_risk: "n/a"` (3 profiles). It is a non-value inside an ordinal scale. Options: drop the field on those profiles (it would have to become optional) or assign a rating. Removing `n/a` from the enum later is itself a MAJOR change.
- `awareness: "negligent"` (1 profile). Negligence is a disposition, not a state of awareness; it also appears as `insider_type: negligent`. Review whether this profile is `unwitting` with `insider_type: negligent`.
- `access_relationship: "insider"` overlaps `category: "insider"` in name. Not wrong, but a reader can confuse the two axes.
- `category_label` duplicates `category` one to one. It is enumerated so the pair cannot drift; a future release could derive it instead of storing it.

Fields left as free strings: `insider_type`, `insider_subtype`, `employment_status`, and `state_actor_type` are optional and sparse (3 to 5 profiles each, 1 to 3 values). They are left open for now. Note that actor-profile `employment_status` uses `current` while `actor_association.employment_status` is an enum of `former` only; reconcile before enumerating.

### Why

The 2.1 schema accepted nonsense: an independent screen of 11 nonsense mutations found the 2.1 schema rejected 1. Every rule above closes a class the review reproduced, using values read from live data so the cut does not reject current content.

### Remediation

For current canonical data, none beyond `schema_version`; every other rule passes on live data. For derived or forked documents: uppercase and hyphenate bibliography keys, use tactic IDs in `related_tactics`, use SemVer versions, keep `severity_band` at or above `severity_floor`, use the enumerated actor-profile values, give every tactic at least one indicator, and set `crossing_mechanism` exactly on `cyber_physical` indicators.

### Example

```jsonc
// 2.1 (validated)                       // 3.0 (required)
{                                        {
  "version": "v1.7",                       "version": "1.7.0",
  "related_tactics": ["recon"],            "related_tactics": ["TM0101"],
  "source_refs": ["ntac mass 2021"],       "source_refs": ["NTAC-MASS-2021"],
  "severity_floor": "critical",            "severity_floor": "critical",
  "severity_band": "low"                   "severity_band": "critical"
}                                        }
```

## Change D: unused stubs

### What changed, with grep evidence

Each stub was checked for consumers with `grep -rn` across `src/`, `examples/`, and `scripts/` on the `v3-design` branch at its base commit `12af1d3`.

| Stub | Consumers found | Decision |
|---|---|---|
| root `operations` | None. `grep -rnw operations src examples scripts` returns one hit, a prose comment in `scripts/release-fulfillment-audit.py` line 111 ("case-operations"), which does not read the field. | **Removed** from the schema. It was never in `required`. The root object is closed, so a document carrying `operations` now fails. |
| indicator `primary_objective_evidence_tier` | Yes. `src/types/framework.ts` line 125 declares it, and `src/components/IndicatorDetail.tsx` lines 191 to 196 render it when present. (`examples/worked-cases/case-4-disrupted-by-interdiction.json` line 14 uses the case-level field on `conditioned_assessment`, not the indicator field.) | **Kept** unchanged. A live consumer reads it. It is not populated on any shipped indicator; the canonical home remains `$defs.conditioned_assessment.primary_objective_evidence_tier`. |
| actor_profile `v2_tactic_associations` | None. `grep -rn v2_tactic_associations src examples scripts` returns no hits. | **Relaxed, not deleted**: removed from `required`, and `items` changed from `{}` to a typed object `{tactic_id, relevance}` (tactic ID pattern; `high`, `medium`, `low`), so a populated future value validates and junk does not. |

### Why

`operations` described a planned V5 composer and held an empty array. Keeping an empty placeholder in a public contract invites consumers to depend on a shape that does not exist. `v2_tactic_associations` was required but always empty and accepted any item, including `null`; it is kept because it names a planned association with a clear shape.

### Remediation

Remove the root `operations` key. Optionally remove `v2_tactic_associations: []` from actor profiles; an empty array still validates. No change for `primary_objective_evidence_tier`.

### Example

```jsonc
// 2.1                                   // 3.0
{                                        {
  "schema_version": "2.1.0",               "schema_version": "3.0.0",
  "operations": [],                        "actor_profiles": [
  "actor_profiles": [                        { "id": "AP001", "...": "..." }
    { "id": "AP001",                       ]
      "v2_tactic_associations": [] }     }
  ]
}
```

## Validation results

Full report: [3.0.0-validation-report.md](./3.0.0-validation-report.md).

- Live 1.7.0 content against the 3.0.0 schema: 124 errors in three categories, all expected. 122 `evidence_basis` enum failures (111 `hybrid`, 10 `operational_primary`, 1 `literature_primary`), 1 `schema_version` pattern failure, 1 unexpected root `operations`. Nothing else fails.
- A migrated copy (those three fixes applied) validates with zero schema errors, passes all 27 `validate.py` checks, and passes 22/22 fixtures.
- Nonsense-mutation screen: the 2.1.0 schema rejects 1 of 11; the 3.0.0 schema rejects 8 of 11. The three it accepts (weight versus axes arithmetic, dangling but well-formed references, cross-tactic placement and duplication) are cross-object invariants held by `validate.py` V02, V06, V09, V12, and V14.

New validator checks and fixtures:

| Check | Gate | Fixture |
|---|---|---|
| V24 | `schema_version` equals `3.0.0` | (fires on every unmigrated document) |
| V25 | `evidence_basis` uses 3.0.0 values | F19: `operational_primary` must fail |
| V26 | lifecycle contract | F20: `deprecated` with `deprecated_in` must pass; F21: `superseded` without `superseded_by` must fail |
| V27 | bibliography key format | F22: malformed dangling `source_refs` entry must fail |

## Consumer checklist

- [ ] Replace `operational_primary`, `hybrid`, and `literature_primary` with `practice_led`, `practice_and_literature`, and `literature_led` wherever you match, filter, or label `evidence_basis`.
- [ ] If you must read both 2.x and 3.x documents, normalize `evidence_basis` on read with the mapping in Change A.
- [ ] Update any check that pins `schema_version` or the schema `$id`.
- [ ] Stop reading the root `operations` key.
- [ ] Treat `v2_tactic_associations` as optional.
- [ ] Treat a missing `lifecycle_state` as `active`; hide `deprecated`, `superseded`, and `reserved` items by default and follow `superseded_by` for historical references.
- [ ] If you generate or fork framework documents, confirm they meet the Change C rules (key and ID patterns, SemVer, actor-profile enums, severity floor, crossing mechanism, non-empty indicators).
- [ ] If you mirror identifiers, diff consecutive ID manifests (`scripts/lint/id-manifest.py --previous`) to confirm nothing was dropped.
- [ ] Re-validate your copy with `python3 scripts/lint/validate.py <your framework.json>` and with the 3.0.0 JSON Schema.
