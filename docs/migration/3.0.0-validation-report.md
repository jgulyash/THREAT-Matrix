# Schema 3.0.0 validation report

Generated 2026-11-02 on branch `v3-design` by running the draft 3.0.0 schema (`docs/data/framework.schema.json`) against the live content document (`docs/data/framework.json`, content version 1.7.0, declared schema 2.1.0) with Python `jsonschema` 4.26.0, Draft 2020-12. Combinator errors from the per-matrix tactic subschemas (`tactic_person` and siblings) are flattened to their leaf causes and de-duplicated, so each count below is one failing value.

## 1. Live document against the 3.0.0 schema

Under the 2.1.0 schema the live document validates with zero errors. Under the 3.0.0 schema it produces 124 errors in three categories. All three are the expected mechanical migration; nothing else in the live data fails the tightened schema.

Totals by category:

- **evidence_basis enum: 122.** 111 `hybrid`, 10 `operational_primary` (TM0103, TF0101, TF0102, TF0103, TF0201, TF0204, TF0206, TF0207, TF0301, TF0401), 1 `literature_primary` (TI0211). The 39 `literature_only` tactics are unchanged and pass. The planning estimate of 161 assumed every tactic would fail; only tactics carrying a renamed value do.
- **schema_version: 1.** The live value `2.1.0` fails the schema pattern (MAJOR 3 pinned) and `validate.py` V24.
- **operations: 1.** The root object is closed (`additionalProperties: false`), so the empty `operations: []` array must be removed from the data.

Categories that were checked and produced **zero** live failures: source_refs key pattern (all 52 bibliography keys and every cited key conform), bibliography propertyNames, related_tactics pattern (451 entries), semver on `version`, severity_floor versus severity_band (43 floored indicators, all `critical`/`critical`), the seven actor-profile enums (32 profiles), tactic `indicators` minItems 1 (no tactic has zero indicators), the cyber_physical crossing_mechanism conditional, the lifecycle conditionals (no live object carries lifecycle fields yet), and `v2_tactic_associations` typed items (every profile carries `[]`, which still validates).

### Data-side fixes the 3.0.0 cut requires

1. Rename `evidence_basis` on 122 tactics: `operational_primary` to `practice_led`, `hybrid` to `practice_and_literature`, `literature_primary` to `literature_led`.
2. Set `schema_version` to `3.0.0`.
3. Remove the root `operations` key.

Optional, not required for validity: remove the empty `v2_tactic_associations: []` from the 32 actor profiles (the field is no longer required). Optional data cleanup of the odd enum value `n/a` in `phase_compression_risk` is described in the migration guide.

A mechanically migrated scratch copy (the three required fixes applied to a copy outside the repository) validates with zero schema errors, passes all 27 `validate.py` checks, and passes 22/22 fixtures.

## 2. Nonsense-mutation screen

Eleven nonsense mutations were applied in memory to the migrated copy, one at a time, and judged by whether the schema reports any error the unmutated copy does not. The same screen was run against the 2.1.0 schema as a baseline.

**The 2.1.0 schema rejects 1 of 11 (mutation 5, through existing minItems rules). The 3.0.0 schema rejects 8 of 11.**

| # | Mutation | 3.0.0 schema | Rejecting rule, or why it is accepted |
|---:|---|---|---|
| 1 | escalation_weight contradicts its axes | Accepted | Arithmetic across fields is out of reach for JSON Schema. Caught by `validate.py` V14. |
| 2 | severity_floor critical with severity_band low | **Rejected** | New severity_floor/severity_band conditional (Change C). |
| 3 | source_refs `NO-SUCH-SOURCE-9999`, correlates_with `IND-9999-99` | Accepted | Both values are well formed. Resolution is a referential check, caught by `validate.py` V09 and V06. |
| 4 | facility indicator placed in a people tactic, then duplicated | Accepted | Parent embedding and uniqueness across array items by key are not expressible. Caught by `validate.py` V12 and V02. |
| 5 | tactic TM0499, phase_name `banana`, empty arrays | **Rejected** | minItems on indicators (new), observed_contexts, source_refs, tactic_families. `phase_name: banana` alone would still pass the schema; `validate.py` V16 catches it. |
| 6 | version `banana`, schema_version empty, license `none` | **Rejected** | New semver patterns on version and schema_version. `license: none` alone would still pass. |
| 7 | bibliography entry keyed `x` with empty title | **Rejected** | New bibliography propertyNames pattern. An empty title alone would still pass. |
| 8 | actor category `space_aliens`, actor_level empty | **Rejected** | New actor-profile enums on category and actor_level. |
| 9 | related_tactics `hello` plus the tactic's own id | **Rejected** | New related_tactics pattern rejects `hello`. A self reference alone would still pass. |
| 10 | operations `[1, "a", null]`, v2_tactic_associations `[null, 42]` | **Rejected** | `operations` removed from a closed root object; typed items on v2_tactic_associations. |
| 11 | modality cyber_physical with no crossing_mechanism | **Rejected** | New conditional: crossing_mechanism required exactly when modality is cyber_physical. |

### Residual gaps (schema accepts, validator catches or nothing catches)

- Mutations 1, 3, and 4 are cross-object or arithmetic invariants. They stay with `validate.py` (V02, V06, V09, V12, V14), which CI runs on every push.
- Partial residuals inside rejected mutations: `phase_name` is a free string (V16 catches mismatches), `license` is a free string, bibliography `title` has no minLength, and `related_tactics` may contain the tactic's own id. Only the first is caught by the validator today; the other three are caught by nothing. None is in the 3.0.0 scope. Adding minLength or a license enum later would be a MAJOR change under docs/VERSIONING.md (it can invalidate previously valid documents), so a native validator check is the cheaper home for the self-reference and empty-title cases.
