# Schema 3.0.0 validation report

Run on 2026-11-15 on branch `v3-design`, locally, with Python 3.14.0 and `jsonschema` 4.26.0 (Draft 2020-12). This report replaces an earlier one that was measured against an unpublished working copy and understated the changes.

It records four things: the gate results on the 3.0.0 files, the published 2.1.0 document measured against the 3.0.0 schema, the result of the migration tool on that document, and a mutation run that shows which gate rejects which kind of defect. It ends with what these results do not show.

Files under test: `docs/data/framework.json` (content 2.0.0, schema 3.0.0), `docs/data/scoring-overlay.json` (overlay 0.1.0), `docs/data/id-manifest.json`, the schemas beside them, and the examples under `examples/`. "The published document" means `docs/data/framework.json` on `origin/main` (content 1.7.0, schema 2.1.0).

## 4. Mutation run

Each negative fixture in `scripts/lint/fixtures` was applied as a mutation and sent through each gate separately: the JSON Schema alone, and the validator's own checks alone with its schema pass switched off. Of the 190 negative fixtures, 185 are mutations of a document. The other 5 are self-tests of the schema checks, which alter a schema file and are not counted here. The runner script is a build aid kept outside the repository; the fixtures it applies are in the repository, and the fixture harness (section 1) runs the same mutations through the combined validator.

| | Count |
|---|---:|
| Mutations | 185 (vocabulary 125, overlay 41, scored record 8, coverage 11) |
| Rejected by the schema alone | 124 |
| Rejected by the validator's own checks alone | 158 |
| Rejected by both | 97 |
| Rejected by the schema only | 27 |
| Rejected by the validator only | 61 |
| Rejected by neither | 0 |

The validator-only cases are rules a schema cannot express: reference resolution, uniqueness across objects, cycles, the weight arithmetic, band fidelity for records, and bare NaN tokens. The schema-only cases are closed-object, enum, and pattern defects that the validator's own checks do not repeat, which is why the validator runs the schemas as a required part of every run.

**Trailing newlines.** Python's regular-expression engine lets a closing `$` match before a final newline, so a plain anchored pattern accepts an identifier with a newline appended. Each anchored pattern in the schemas is therefore paired with a second pattern that rejects whitespace. Checked directly: `TM0101` followed by a newline as a tactic identifier, and `2.0.0` followed by a newline as the version, are each rejected by Python `jsonschema` alone, and the validator's exact full match rejects them as well. The schema patterns were not run under a JavaScript validator.

## 5. What these results do not show

- **They are local runs.** The same commands are in the continuous-integration workflows, which trigger on this branch. This report does not record a run on GitHub.
- **They say nothing about whether the content is right.** No gate reads a behavior description for accuracy, checks that a cited source supports the entry that cites it, or checks that a URL resolves.
- **They do not validate the scoring overlay.** The overlay checks confirm that the file is internally consistent: weights follow from axes, bands follow from stored weights and floors, labels follow from their rule. They cannot show that any authored value is right. The overlay is experimental and unvalidated.
- **Some stated rules are not checked by any gate.** They are listed in [METHODOLOGY.md](../METHODOLOGY.md#what-the-gates-do-not-check).
- **No reliability study has been run.** See [docs/study/README.md](../study/README.md).
