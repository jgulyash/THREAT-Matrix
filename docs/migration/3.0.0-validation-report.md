# Schema 3.0.0 validation report

Run on 2026-11-15 on branch `v3-design`, locally, with Python 3.14.0 and `jsonschema` 4.26.0 (Draft 2020-12). This report replaces an earlier one that was measured against an unpublished working copy and understated the changes.

It records four things: the gate results on the 3.0.0 files, the published 2.1.0 document measured against the 3.0.0 schema, the result of the migration tool on that document, and a mutation run that shows which gate rejects which kind of defect. It ends with what these results do not show.

Files under test: `docs/data/framework.json` (content 2.0.0, schema 3.0.0), `docs/data/scoring-overlay.json` (overlay 0.1.0), `docs/data/id-manifest.json`, the schemas beside them, and the examples under `examples/`. "The published document" means `docs/data/framework.json` on `origin/main` (content 1.7.0, schema 2.1.0).

## 4. Mutation run

Each of the 147 negative fixtures in `scripts/lint/fixtures` was applied as a mutation and sent through each gate separately: the JSON Schema alone, and the validator's own checks alone with its schema pass switched off. The runner script is a build aid kept outside the repository; the fixtures it applies are in the repository, and the fixture harness (section 1) runs the same mutations through the combined validator.

| | Count |
|---|---:|
| Mutations | 147 (vocabulary 102, overlay 31, scored record 8, coverage 6) |
| Rejected by the schema alone | 89 |
| Rejected by the validator's own checks alone | 141 |
| Rejected by both | 83 |
| Rejected by the schema only | 6 |
| Rejected by the validator only | 58 |
| Rejected by neither | 0 |

The 6 schema-only cases are closed-object and enum defects that the fixtures use to prove the two schema checks. The 58 validator-only cases are rules a schema cannot express: reference resolution, uniqueness across objects, cycles, the weight arithmetic, band fidelity for records, bare NaN tokens, and trailing newlines.

**Trailing newlines.** Eight of the validator-only mutations append a newline to an identifier, key, or version. Python's `jsonschema` accepts them, because Python's regular-expression engine lets a closing `$` match before a final newline. The validator rejects them with an exact full match. A consumer that runs only a Python JSON Schema validator will accept such values. The schema patterns were not run under a JavaScript validator, where `$` is strict by definition; that expectation rests on the language definition, not on a run.

## 5. What these results do not show

- **They are local runs.** The same commands are in the continuous-integration workflows, which trigger on this branch. This report does not record a run on GitHub.
- **They say nothing about whether the content is right.** No gate reads a behavior description for accuracy, checks that a cited source supports the entry that cites it, or checks that a URL resolves.
- **They do not validate the scoring overlay.** The overlay checks confirm that the file is internally consistent: weights follow from axes, bands follow from stored weights and floors, labels follow from their rule. They cannot show that any authored value is right. The overlay is experimental and unvalidated.
- **Some stated rules are not checked by any gate.** They are listed in [METHODOLOGY.md](../METHODOLOGY.md#what-the-gates-do-not-check).
- **No reliability study has been run.** See [docs/study/README.md](../study/README.md).
